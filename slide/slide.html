Why I created it

  • I wanted to run Julia on my iPad
  • But Julia normally relies on JIT compilation — and iOS blocks JIT twice:
    • The OS blocks it — W^X: memory is writable xor executable
      • A JIT writes machine code, then executes it
      • → it needs pages it can write and then execute
      • General-purpose JIT is unavailable to ordinary distributed apps — Apple reserves it for its own apps like Safari’s JS engine (exceptions: approved browser engines, debugger-attached dev builds) — Apple Platform Security
    • The store forbids it
      • Apps may not download, install, or execute code that introduces or changes app functionality — App Store Review Guidelines §2.5.2
  • A bundled interpreter is fine: bytecode is just data read by an already-signed app (downloaded code would still fall under §2.5.2)

What about Binder or Google Colab?

  • Unusable where the internet connection is unreliable
  • Installing external packages takes a long time

How I created it

  • Apps like Pythonista and Carnets do run on iOS.
    • So why not build a virtual machine that accepts Julia syntax?!
  • I don’t have an ability to create this

How sjulia differs from official Julia

How code is interpreted and executed:

Each cell: who does it → what it produces

Stage Official Julia SubsetJuliaVM
Parsing flisp / JuliaSyntax.jl → AST pure-Rust parser → CST
Lowering Julia’s lowering → lowered IR Rust lowering → Core IR
Code generation LLVM JIT at runtime → native code bytecode compiler before execution → bytecode
Execution CPU runs native code stack VM interprets bytecode
Runtime library C runtime + pure-Julia base/ Rust builtins + a pure-Julia subset
  • With no JIT, SubsetJuliaVM runs even on iOS (W^X) and WASM

What SubsetJuliaVM does not provide

Everything that would break the sandboxed, offline, no-downloaded-code model:

  • Pkg.jl / package management — no Pkg.add, no registry, no downloads; using X only reaches the ~34 packages bundled into the binary
  • Network I/O — no Sockets, no Downloads/HTTP
  • Filesystem access — file operations are unimplemented; include resolves through virtual embedded paths
  • External processes — no run(cmd)
  • C interface — no @ccall/pointer/unsafe_*
  • Real parallelism — single-threaded by design; Tasks/Channels are cooperative continuations
  • Native-code reflection — no @code_llvm/@code_native (there is no LLVM); use sjulia --dump-bytecode instead

Performance: Julia vs. SubsetJuliaVM

Mandelbrot set benchmark (Apple Silicon macOS, measured 2026-07):

function mandel_point(c::ComplexF64,
                      maxiter::Int64)::Int64
    z = 0.0 + 0.0im
    for k in 1:maxiter
        abs2(z) > 4.0 && return k - 1
        z = z * z + c
    end
    return maxiter
end

function mandel_count(width, height, maxiter)
    total = 0
    for y in 1:height
        ci = -1.2 + 2.4 * (y - 1) / (height - 1)
        for x in 1:width
            cr = -2.0 + 3.0 * (x - 1) / (width - 1)
            total += mandel_point(cr + ci * im, maxiter)
        end
    end
    total
end
